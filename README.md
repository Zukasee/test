# PEPTIDE / SELECT — лендинг с квизом

Статичный лендинг (`index.html`) + обработчик заявок, который пересылает их в Telegram.
Токен бота хранится **только на сервере**, в HTML его нет.

```
index.html          — лендинг (hero, квиз из 2 вопросов, форма контактов)
privacy.html        — шаблон политики конфиденциальности (заполнить!)
assets/             — изображения (og.jpg — превью для соцсетей)
api/lead.js         — обработчик для Vercel        → POST /api/lead
api/_lead-core.js   — общая логика (валидация, формат сообщения, отправка)
api/lead.php        — обработчик для PHP-хостинга  → POST /api/lead.php
scripts/            — локальный сервер и тесты
_design/            — исходный макет (на сайт не выкладывается)
```

## 1. Telegram-бот

1. В Telegram откройте **@BotFather** → `/newbot` → получите токен вида `123456789:AA...`.
2. Решите, куда падают заявки:
   - **в личку** — напишите своему боту `/start`;
   - **в группу** (удобно для нескольких менеджеров) — создайте группу и добавьте туда бота.
3. Узнайте `chat_id`: после шага 2 откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`.
   У групп id отрицательный (`-100...`). Если ответ пустой — напишите что-нибудь в чат и обновите страницу.

Несколько получателей — через запятую: `TELEGRAM_CHAT_ID=-100111,222333`.

## 2. Деплой

### Вариант A — Vercel (рекомендую, бесплатно)

1. Залейте папку в GitHub-репозиторий и импортируйте его на vercel.com (Framework: **Other**, без сборки).
   Или без GitHub: `npx vercel` в этой папке.
2. *Settings → Environment Variables*: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
   (необязательно: `ALLOWED_ORIGINS=https://ваш-домен.ru`). Список — в `.env.example`.
3. Redeploy → подключите свой домен в *Settings → Domains*.

> Домены `*.vercel.app` в РФ открываются нестабильно — для рекламы обязательно подключите свой домен.

Netlify/Cloudflare тоже подойдут, но обработчик придётся обернуть под их формат функций — `_lead-core.js` переиспользуется как есть.

### Вариант B — обычный хостинг с PHP (Beget, Timeweb, REG.RU…)

1. В `index.html` в блоке `CONFIG` замените `endpoint: "/api/lead"` на `endpoint: "/api/lead.php"`.
2. Скопируйте `api/config.example.php` → `api/config.php` и впишите токен и chat_id.
3. Загрузите на хостинг: `index.html`, `privacy.html`, `favicon.svg`, `assets/`, `api/lead.php`, `api/config.php`, `api/.htaccess`.
   (`_design/`, `scripts/`, `api/*.js` выкладывать не нужно.)
4. Нужен PHP 7.4+ с расширениями curl и mbstring (на всех популярных хостингах есть).

## 3. Перед публикацией — чек-лист

- [ ] Реквизиты в футере `index.html` (строка с `[Наименование ИП/ООО, ИНН, ОГРН]`).
- [ ] Все жёлтые поля в `privacy.html` (оператор, ИНН, e-mail, домен, срок хранения).
- [ ] `og:image` в `<head>` — заменить на абсолютный URL: `https://ваш-домен.ru/assets/og.jpg` (иначе превью в мессенджерах не подтянется).
- [ ] Яндекс.Метрика (по желанию): вставить код счётчика перед `</head>` и указать номер в `CONFIG.ymId` — при успешной заявке сработает цель `lead`.
- [ ] Отправить тестовую заявку с боевого домена и убедиться, что она пришла в Telegram.

## Локальная разработка

Нужен Node.js 18+.

```bash
npm run dev    # http://localhost:3000
npm test       # тесты обработчика
```

Без `.env` dev-сервер работает в режиме заглушки: заявки не уходят в Telegram, а печатаются в консоль.
Чтобы проверить реальную отправку — скопируйте `.env.example` в `.env` и заполните.

## Что умеет обработчик

- Валидация: имя, контакт (`@username`, `t.me/...` или телефон 10–15 цифр), обязательное согласие на ПДн.
- Антиспам: скрытое поле-ловушка, отсев слишком быстрых отправок, лимит 5 заявок с IP за 10 минут.
- В сообщении: имя, кликабельный контакт (ссылка на Telegram или `tel:`), ответы квиза, UTM-метки, страница, источник, время (МСК) и IP.
- Если указано несколько чатов и один недоступен — заявка всё равно доставляется в остальные.
